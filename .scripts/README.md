# 需求：视频播放器横竖屏、倍速播放与手势交互优化

## 需求背景

当前项目的视频播放页面由 `VideoPlayerActivity` 承载，视频模式使用 `VideoPlayerView` 和 `CommonPlayerVideoEngine`，底层同时支持 ExoPlayer 与 FFmpeg 播放引擎。

现有实现具备以下基础能力：

- `VideoPlayerEngine` 已提供 `setPlaybackSpeed(speed)` 接口。
- `VideoPlayerView` 已保存当前 `playbackSpeed`，并通过 `setSpeed()` 设置播放倍速。
- `CommonPlayerVideoEngine` 会同时设置 FFmpeg 音频和视频倍速，音频切速失败时会回退，避免持续音画不同步。
- `VideoPlayerActivity` 已在 Manifest 中声明 `orientation|screenSize|keyboardHidden`，可以在方向变化时复用当前 Activity。
- `CommonPlayerVideoEngine` 已处理 Surface 销毁、音视频成对暂停和 Surface 重建后的恢复。
- 播放器已支持横向滑动快进/快退，以及左右两侧纵向滑动调节亮度和音量。

当前仍存在以下限制：

- 视频页面通过 `SCREEN_ORIENTATION_LANDSCAPE` 强制横屏，没有手动横竖屏切换入口。
- 播放器底部控制栏没有倍速选择入口。
- 没有长按临时加速播放能力。
- 横向滑动快进/快退的当前换算规则为滑动整个播放器宽度约调整 60 秒，需提升到当前灵敏度的 1.5 倍。
- FFmpeg 音频缓冲当前按最高 `2.0x` 倍速预留，需要验证并支持稳定的 `3.0x` 播放。

## 需求目标

本次需要完成以下四项功能：

1. 视频播放页面支持手动横竖屏切换，切换时不重新加载视频、不丢失播放进度，并避免方向切换后立即反向回弹。
2. 增加 `0.75x`、`1.0x`、`1.25x`、`1.5x`、`2.0x`、`3.0x` 六档常驻倍速选择。
3. 播放过程中长按视频区域临时进入 `3.0x` 播放，松手后恢复长按前的常驻倍速，并显示中文状态提示。
4. 将现有横向滑动快进/快退灵敏度调整为当前值的 `1.5` 倍。

所有功能必须兼容当前的播放进度、暂停恢复、音画同步、Surface 生命周期和控制面板逻辑。

## 功能要求

### 1. 横竖屏切换

#### 1.1 切换入口与位置

- 在播放器底部控制栏增加横竖屏切换按钮。
- 控制栏从左到右的顺序应为：
  1. 当前播放时间。
  2. 播放进度条。
  3. 视频总时长。
  4. 倍速按钮。
  5. 横竖屏切换按钮。
- 横竖屏按钮必须位于进度条之后，并位于倍速按钮之后。
- 当前为竖屏时显示“切换横屏”语义的图标。
- 当前为横屏时显示“切换竖屏”语义的图标。
- 按钮需要提供无障碍描述，不得只依赖图标表达功能。

#### 1.2 默认方向

- 视频首次进入 `VideoPlayerActivity` 时，继续沿用当前默认横屏行为。
- 音频文件继续沿用现有方向策略，不纳入本次视频横竖屏切换功能。

#### 1.3 手动切换规则

- 点击横竖屏按钮时，按当前实际方向切换到目标方向：
  - 横屏切换为竖屏。
  - 竖屏切换为横屏。
- 同一次点击只允许发起一次方向请求。
- 方向请求发出后，在系统回调确认目标方向之前，不允许再次根据旧方向发起反向请求。
- 必须记录“当前方向”“目标方向”和“是否正在切换”状态。
- 只有系统配置已经切换到目标方向后，才能清除切换中状态并更新按钮图标。

#### 1.4 防止方向立即回弹

- 手动切换到横屏后，不得因为传感器、旧的方向状态、重复点击回调或重新设置 `UNSPECIFIED`，立即切回竖屏。
- 手动切换到竖屏后，同样不得立即切回横屏。
- 手动方向切换期间应忽略重复方向事件。
- 不得在方向切换完成后立即把 `requestedOrientation` 恢复为可能触发反向旋转的模式。
- 连续快速点击横竖屏按钮时，应忽略切换完成前的后续点击，或只保留最终有效目标，不得来回抖动。

#### 1.5 播放状态保持

横竖屏切换时必须复用当前播放器实例，不得执行以下操作：

- 不得重新创建 `VideoPlayerView` 或 `VideoPlayerEngine`。
- 不得重新调用 `setVideoPath()`。
- 不得重新设置媒体数据源。
- 不得重新执行完整的 `initData()`、`prepare()`、`start()` 流程。
- 不得先 `release()` 再重新创建播放器。
- 不得通过额外 `seekTo()` 模拟进度恢复。

切换前后必须保持：

- 当前播放进度。
- 播放或暂停状态。
- 用户选择的常驻倍速。
- 音画同步状态。
- 当前总时长和进度条状态。
- 播放完成状态。
- 控制栏锁定状态。

如果方向切换导致 Surface 销毁：

- 音频和视频必须成对暂停。
- Surface 重建后，仅当切换前处于播放状态时才自动继续播放。
- 切换前处于暂停状态时，Surface 重建后仍须保持暂停。
- 不得出现重复音频、后台残留声音或多个播放器实例。

#### 1.6 画面与布局适配

- 横竖屏切换后，应根据新的容器宽高重新计算视频 Surface 尺寸。
- 保持当前 `VideoScaleType` 的显示语义，不得非等比拉伸。
- 视频画面在横屏和竖屏下均保持居中。
- 底部时间、进度条、倍速按钮和方向按钮不得重叠或超出屏幕。
- 系统栏或手势区域不得遮挡底部按钮。
- 横竖屏切换后继续保持现有沉浸式播放效果。

### 2. 常驻倍速播放

#### 2.1 倍速档位

播放器必须提供以下六档倍速：

- `0.75x`
- `1.0x`
- `1.25x`
- `1.5x`
- `2.0x`
- `3.0x`

除以上档位外，UI 不允许输入任意倍速。

#### 2.2 倍速按钮与选择面板

- 在底部控制栏增加倍速按钮。
- 倍速按钮位于视频总时长之后、横竖屏切换按钮之前。
- 按钮默认显示 `1.0x`。
- 按钮应实时显示当前实际生效的常驻倍速。
- 点击倍速按钮后，展示包含六个档位的单选列表或轻量选择面板。
- 当前已选择档位需要有明确选中状态。
- 点击某个档位后立即尝试应用并关闭选择面板。
- 倍速应用成功后才更新按钮文本和选中状态。
- 倍速应用失败时保持原倍速，并通过现有错误回调或轻提示告知用户，不得让音频和视频停留在不同倍速。

#### 2.3 倍速状态保持

- 用户选中的倍速在同一次播放器页面生命周期内保持有效。
- 横竖屏切换后保持当前倍速。
- 页面进入后台再返回后保持当前倍速。
- 暂停、恢复、拖动进度和 Surface 重建后保持当前倍速。
- 播放结束后在当前页面点击重播，继续使用用户已选择的倍速。
- 退出播放器页面并重新进入时，默认恢复为 `1.0x`，本期不做跨页面记忆。

#### 2.4 音画同步与 3 倍速支持

- ExoPlayer 和 FFmpeg 视频引擎都必须支持六档倍速。
- FFmpeg 播放时必须同时修改音频输出速度、视频时钟和视频渲染速度。
- `3.0x` 播放不能只修改视频速度或只修改音频速度。
- FFmpeg 音频缓冲区、AudioTrack PlaybackParams 和 native 播放时钟需要支持最高 `3.0x`。
- 如果目标设备的 AudioTrack 拒绝某个倍速，应整体回退到切换前倍速，不得造成持续音画不同步。
- 常驻倍速切换不得改变当前播放进度。

### 3. 长按临时 3 倍速播放

#### 3.1 触发区域与条件

- 用户在视频画面空白区域长按时，临时切换为 `3.0x` 播放。
- 长按时间使用系统长按判定时间，不自行设置过短时间导致误触。
- 手指移动距离未超过系统 touch slop 时才允许触发长按。
- 以下场景不得触发临时 3 倍速：
  - 播放器处于暂停状态。
  - 播放器处于加载或错误状态。
  - 视频已经播放完成。
  - 播放器处于锁定状态。
  - 用户正在拖动进度条。
  - 用户按在倍速按钮、方向按钮或其他控制按钮上。
  - 多指触摸。

#### 3.2 临时倍速规则

- 长按生效时保存长按前的常驻倍速。
- 临时倍速统一设置为 `3.0x`。
- 手指抬起后恢复到长按前的常驻倍速：
  - 长按前为 `1.0x`，松手后恢复 `1.0x`。
  - 长按前为 `1.5x`，松手后恢复 `1.5x`。
  - 其他档位按相同规则恢复。
- 如果长按前已经是 `3.0x`，长按期间仍可展示提示，松手后保持 `3.0x`。
- 临时 3 倍速不改变倍速按钮记录的常驻倍速和选中状态。
- 临时切速失败时不得展示“当前3倍速度播放中”的成功状态，并保持长按前倍速。

#### 3.3 中文提示

- 长按 3 倍速生效时，在播放器页面顶部居中展示：

```text
当前3倍速度播放中
```

- 提示使用单独的 `TextView`，不得复用音量、亮度、快进/快退的中央提示区域。
- 文本使用白色或项目现有适合深色背景的高对比度颜色。
- 文本背景必须使用 shape drawable 实现。
- shape 背景应包含：
  - 半透明深色背景。
  - 合理圆角。
  - 横向和纵向内边距。
  - 不影响文字可读性的透明度。
- 提示位置应考虑状态栏和安全区域，不得贴边或被系统栏遮挡。
- 提示不跟随控制面板自动隐藏，长按期间持续可见。

#### 3.4 结束与异常恢复

出现以下任一事件时，必须结束临时 3 倍速、隐藏提示，并恢复长按前倍速：

- `ACTION_UP`
- `ACTION_CANCEL`
- 触摸转为多指操作
- 页面进入后台
- Activity 失去播放状态
- 播放器暂停
- 播放器完成
- 播放器发生错误
- Surface 销毁
- 横竖屏配置发生变化
- `VideoPlayerView.destroy()`

恢复操作必须幂等，同一次长按只能恢复一次，不得因多个结束回调重复切速。

#### 3.5 与现有手势的冲突处理

- 长按一旦生效，本次触摸序列不得再触发横向快进/快退。
- 长按一旦生效，本次触摸序列不得再触发纵向亮度或音量调节。
- 长按结束时不得执行 `seekTo()`。
- 手指在长按生效前明显横向移动时，应取消长按判定并进入快进/快退手势。
- 手指在长按生效前明显纵向移动时，应取消长按判定并进入亮度或音量手势。
- 普通单击显示/隐藏控制面板的现有行为保持不变。

### 4. 横向滑动快进/快退调整为当前灵敏度的 1.5 倍

#### 4.1 换算规则

- 当前实现中，横向滑动整个播放器宽度约对应 60 秒进度变化。
- 调整后，横向滑动整个播放器宽度应约对应 90 秒进度变化。
- 新换算值等于当前换算值乘以 `1.5`。
- 相同滑动距离下，快进或快退的秒数应为当前版本的 `1.5` 倍。
- 不得把“1.5 倍”理解为把播放速度切换为 `1.5x`。

#### 4.2 手势行为

- 向右滑动继续表示快进。
- 向左滑动继续表示快退。
- 快进/快退提示继续展示目标调整秒数和对应方向图标。
- 调整后的目标位置必须限制在 `[0, duration]` 范围内。
- 到达开头或结尾时不得越界。
- 手指移动过程中只预览目标变化，抬起后只执行一次实际 `seekTo()`。
- `ACTION_CANCEL` 时沿用项目现有语义，但必须保证不会重复 seek。
- 横向手势识别应以横向位移达到 touch slop 为准，不应要求用户先产生明显纵向位移。
- 纵向亮度和音量手势的灵敏度保持不变。

## 状态优先级

播放器同时存在常驻倍速、临时倍速和生命周期状态时，按以下优先级处理：

1. 错误、销毁、播放完成：停止临时倍速并清理提示。
2. 页面暂停、Surface 销毁、方向切换：结束临时倍速，恢复常驻倍速后再处理暂停或重建。
3. 长按临时倍速：播放期间暂时覆盖常驻倍速。
4. 用户选择的常驻倍速：作为正常播放倍速长期保持。
5. 默认倍速：`1.0x`。

任何状态变化都不得造成音频和视频使用不同倍速。

## 验收标准

### 1. 横竖屏切换

1. 视频播放 10 秒后点击方向按钮，能够在横屏和竖屏之间切换。
2. 切换后不重新加载媒体，不重新进入加载态，不从 `00:00` 开始。
3. 播放中切换后继续播放，额外进度偏差不超过 `1 秒`。
4. 暂停时切换后仍保持暂停，进度偏差不超过 `300ms`。
5. 切换到横屏后不会立即自动切回竖屏，切换到竖屏后也不会立即自动切回横屏。
6. 连续完成 10 次横竖屏切换，不崩溃、不重复播放、不残留音频。
7. 切换后视频画面等比显示，控制栏和按钮不越界。
8. 倍速按钮位于总时长之后，方向按钮位于倍速按钮之后。

### 2. 常驻倍速

1. 倍速面板完整展示六个档位。
2. 每个档位均可成功切换，按钮文本与实际倍速一致。
3. 切换倍速时当前播放进度连续，不回退、不归零。
4. `0.75x`、`1.0x`、`1.25x`、`1.5x`、`2.0x`、`3.0x` 下音画同步，无持续累积偏差。
5. 横竖屏、暂停恢复、拖动进度、前后台切换后保持用户选择的常驻倍速。
6. 退出播放器重新进入后默认显示并使用 `1.0x`。
7. 切速失败时音频和视频均保持原倍速，并有明确失败反馈。

### 3. 长按临时 3 倍速

1. `1.0x` 播放时长按视频区域，成功切换为 `3.0x`，顶部显示“当前3倍速度播放中”。
2. 松手后立即隐藏提示并恢复 `1.0x`。
3. 常驻 `1.5x` 时长按进入 `3.0x`，松手后恢复 `1.5x`。
4. `ACTION_CANCEL`、后台切换、暂停、错误、播放完成、方向切换和销毁均能恢复长按前倍速。
5. 长按期间不会同时触发快进、快退、音量或亮度手势。
6. 长按结束不会改变当前播放位置，也不会额外执行 seek。
7. 提示位于顶部居中，shape 背景、文字、圆角和内边距显示正常。
8. 锁定、暂停、加载、结束或点击控制按钮时不会误触临时 3 倍速。

### 4. 快进/快退灵敏度

1. 相同滑动距离下，新版本调整秒数约为当前版本的 `1.5` 倍。
2. 横向滑动整个播放器宽度约对应 90 秒。
3. 向右快进、向左快退的方向保持正确。
4. 目标位置不会小于 0 或超过总时长。
5. 松手后只执行一次 seek，不发生重复跳转。
6. 纵向亮度和音量调节不受影响。

### 5. 组合场景

需要覆盖以下组合测试：

- 选择 `0.75x` 后横竖屏切换。
- 选择 `1.5x` 后暂停、恢复和拖动进度。
- 选择 `2.0x` 后长按临时 `3.0x`，松手恢复 `2.0x`。
- 常驻 `3.0x` 时长按和松手。
- 长按期间触发 Activity 暂停或方向变化。
- 横向滑动后立即切换方向。
- 横竖屏切换后立即选择倍速。
- 视频接近结束时执行倍速和方向切换。
- 无音频轨视频使用全部倍速档位。

### 6. 构建与设备验证

- 执行 `:demo:assembleDebug` 并构建通过。
- 涉及 FFmpeg/AudioTrack 时，在 `arm64-v8a` 或 `armeabi-v7a` 真机验证。
- 至少覆盖 Android 7.0、Android 10、Android 13 及 Android 15 中可获得的代表设备或模拟器。
- `3.0x` 下不得出现持续音画不同步、重复声音、明显爆音或播放器崩溃。
- 最终 Diff 不得包含无关的微信分享、AOP 版本、签名或发布配置修改。
